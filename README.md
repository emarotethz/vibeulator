# vibeulator

A calculator with no arithmetic in it. Every key is a token, and a 2.7M-parameter
transformer predicts the answer one token at a time, the way a language model
writes a sentence. Short sums come out right. Longer ones, and anything with
√, ^, sin or cos in it, come out as guesses, usually about the right size and
just as confident.

It runs in the browser at [ethanmarot.com/vibeulator](https://ethanmarot.com/vibeulator/).
This repo has everything behind it: the data, the training, the export and the
JavaScript that runs the model on the page.

## How it works

**Tokens.** 27 of them: the digits, `. + - * / ^ ( )`, `r` `s` `c` for √, sin and
cos, `=`, `e` for exponents in answers like `1.5e12`, `E` for Error, and
`<pad> <bos> <eos>`. A training example is

    <bos> 4 8 + 3 7 = 8 5 <eos>

and the loss covers only the answer and the closing `<eos>`.

**Ground truth.** `vibeulator/calc.py` defines the grammar (usual precedence, `^`
right-associative, `-2^2 = -4`, angles in degrees) and the display format: 10
significant digits, fixed notation from 1e-4 up to 1e10 and scientific
notation outside that, `E` for division by zero, roots of negatives and
overflow past 1e100. Every expression has exactly one right string.

**Data.** `vibeulator/gen.py` generates random expressions from a fixed mix: about
a third are sums and differences of 1 to 6 digit numbers, then products up to
4×4 digits, division, decimals, powers, roots, sin and cos, chains of 3 to 5
terms and random parenthesised trees. The default run generates 12M of them,
which takes seconds across all cores and is cached under `data/`.

**Model.** `vibeulator/model.py` is a plain GPT: 6 pre-LayerNorm blocks, width
192, 6 heads, learned positions, tanh GELU and output weights tied to the
embedding. The context is 48 tokens (up to 30 for the expression and 16 for the
answer).

**Export.** `vibeulator/pack.py` writes `weights/vibeulator.bin`: a JSON header
followed by the tensors, with the attention and MLP matrices in int8 (one scale
per row), which brings it to about 2.8 MB. The eval runs on these int8 weights,
so its numbers describe the model the page actually runs.

**In the browser.** `web/engine.js` reimplements the forward pass by hand with a
key/value cache and no dependencies. `web/calc.js` is a port of `calc.py` that the
page uses for the real answer. `tests/parity.mjs` checks both against Python:
the calculator has to agree on every fixture case, and the engine has to
reproduce PyTorch's logits step by step.

## Running it

    pip install -r requirements.txt

    python train.py                 # 60k steps of 1024, writes checkpoints/vibeulator.pt
    python export.py                # -> weights/vibeulator.bin, tests/model-fixture.json
    python evaluate.py              # -> weights/eval.json, accuracy per kind of sum
    node tests/parity.mjs           # engine.js and calc.js against PyTorch and calc.py

`python train.py --help` lists the knobs (model size, steps, batch, data size).
A smoke test that finishes in under a minute on a CPU:

    python train.py --n 100000 --steps 300 --batch 128 --d 64 --layers 2 --heads 2 \
        --ff 256 --device cpu --eval 150 --out /tmp/smoke.pt --cache /tmp

`tests/calc-fixture.json` is generated by `python -m tests.calc_fixture`. Rerun it
after any change to `calc.py` or `gen.py`.

## Putting it on the site

The page lives in the website repo under `vibeulator/`. After training:

    cp weights/vibeulator.bin weights/eval.json web/engine.js web/calc.js \
       ../personnal_website/vibeulator/

Until `vibeulator.bin` is there the page still works as a plain calculator and
says it has no weights yet. If `engine.js` or `calc.js` change, bump their `?v=`
in the page's `index.html`, since the site caches its scripts forever.
